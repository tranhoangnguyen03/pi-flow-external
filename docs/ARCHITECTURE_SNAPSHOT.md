## 1. Intent & routing

Fork of pi-flow. Ordinary driver: `Agent`, optional `workflow`, read-only `external_help`, `external_runs`. `pi_flow_role_create` only inside `/external role create`. `pi_flow_harness_create` only inside `/external harness create`. `/external profiles`, `/external profile create`, and `/pi-flow-profile create` are removed, with no alias. `subagent_type` remains the exact-identity API. Native Pi work → Pi subagent tool. Everything else → this extension.

6 harnesses: `claude` (CLI) · `codex` (CLI) · `agy` (CLI, always `--dangerously-skip-permissions`) · `grok` (CLI, official Grok Build CLI verified against `1.0.40`, native `--sandbox` axis) · `muse` (CLI, Muse Code verified against `1.3.0`, envelope JSONL protocol, approval/sandbox flags) · `pi-*` (registered in-process configs, not a CLI). `pi-*` runs via `createAgentSession` with parent's live `modelRegistry` instance.

## 2. System map

- `index.ts` → `src/pi-subagent.ts` — lifecycle, flags `--max-concurrent-subagents`/`--subagent-timeout-ms`, `Agent` tool, `buildCoordinatorPrompt` injection, status line.
- `src/profiles.ts` — `loadExternalCatalog` is the one roster for Agent, workflow, coordinator guidance, `external_help`, `/external roles`, and doctor. Precedence: exact `overrides/<identity>.md`, then shared `roles/<role>.md`, then the in-memory built-in. An invalid higher-priority entry blocks that selection. Unrelated invalid entries stay diagnostics. `disabledProfiles` blocks `role` and exact `subagent_type`. Native `subagents/*.md` stays outside the catalog. `resolveExternalProfile` throws at selection. Pi `model`/`thinking` reconcile to the settings harness entry; a conflicting pin is a hard error at selection.
- `src/default-roles.ts` — 6 roles `explorer/planner/implementer/reviewer/qa/worker` (dependency-free leaf), bound in memory to `agy`, `claude`, `codex`, `grok`, `muse`, and every registered `pi-*` harness. Session start writes zero role files and zero seed markers.
- `src/defaults.ts` — historical seed-cohort names for the one-time upgrade and the purge inventory (the exact 30 `<agy|claude|codex|grok|muse>-<explorer|planner|implementer|reviewer|qa|worker>` files, plus markers v1/v2/v3). The contract is that session start does not seed.
- `src/harnesses.ts` — `pi-*` name / `provider/model` / thinking (`off|minimal|low|medium|high|xhigh`) validation. Storage is the settings v4 `harnesses` object. There is no live `harnesses.json` writer.
- `src/settings.ts` — v4 `defaultHarness/maxConcurrentSubagents/subagentTimeoutMs/defaultPermission/defaultMaxBudgetUsd/maxRunRecords/harnesses/disabledProfiles`. Missing file uses in-memory defaults and does not write. Malformed JSON or an unsupported version blocks delegation. One staged read-modify-write; unrelated fields preserved; future-version files refused. No inter-process lock (last-writer-wins remains accepted). Trusted project `.pi/pi-flow-external/settings.json` may override only `defaultHarness`. Precedence: call harness > project > global > built-in `agy`. A stale `pi-*` default fails the call and does not fall back to `agy`.
- `src/config-upgrade.ts` — isolated from `loadExternalCatalog`. `/external settings convert` previews and applies one conversion: merge valid settings and named harnesses, copy customized external profiles to exact overrides, record deleted seeded identities in `disabledProfiles`, keep originals, install copies, then activate v4. `/external settings` points at that command when a plan is ready. After activation, old paths are ignored. Interrupted conversion accepts identical copies and rejects differing collisions. The next invocation reads the activated catalog. `maxConcurrentSubagents` is replaced only when the limiter has no active and no queued work (`src/pi-subagent.ts`). A workflow freezes its catalog at start (`src/workflow/tool.ts`). `/external [danger]purge-old-files` lists the legacy inventory (seeded names, harness-prefixed custom CLI profiles, structurally identified `pi-<label>-<role>.md` files, the three seed markers, and `harnesses.json`), including customized copies, then deletes only the individually selected paths after confirmation. It requires completed v4 conversion. It skips symlinks and non-regular entries, does not recurse, and does not remove `subagents/` itself, native profiles, current settings/roles/overrides, project configuration, or run evidence.
- `src/profile-creator.ts` — `/external role create` writes one shared role offline via `pi_flow_role_create`. `/external harness create` smoke-tests and commits one `pi-*` settings entry via `pi_flow_harness_create`. Old profile-create routing is gone.
- `src/external-command.ts` — `/external`, `doctor`, `settings`, `settings edit`, `settings convert`, `harnesses`, `harness create`, `roles`, `role create`, `role inspect <role> [harness]`, `role override <role> <harness>`, literal `[danger]purge-old-files`, `workflows`, `runs`, `runs summary`, `runs --prune`, `help`. Doctor separates catalog validity from CLI/Pi readiness.
- `src/core/spawn.ts:846` — shared primitive: `resolveEffectivePermissionTier` → `resolvePermission`, optional `resumeRunId` resolve, `createTimeoutSignal`, `recordRun`, dispatch to `claude/codex/agy/grok/muse/pi`. Outer `spawnSubagent` handles timeout rewrite, abort mapping, receipt banner, durable finish. `hasNestedAgentActivity` treats `grok` like `claude` (assistant message `tool_use` blocks); `isNestedToolName` includes Grok's own `spawn_subagent` tool id; `muse` dispatches to `museHasNestedAgentActivity`, which always returns `false` (no confirmed real delegation event exists — see §3).
- `src/core/permissions.ts` — single source `PI_TIER_ACTIVE_TOOLS`; execution lanes (`implementer/qa/worker` + `permission:danger`) floor `edit→danger` on `claude`/`pi`; `agy` elevates every tier to `danger`; `grok`/`muse` need no floor (their `edit` tiers already permit shell — `--sandbox workspace` / sandbox left enabled with only approval bypassed); `permissionLabel` — CLIs `unsandboxed external CLI` vs Pi `Pi SDK child · host access · curated tools`.
- `src/core/claude|codex|agy|grok|muse.ts` — CLI adapters, stream-json/envelope parsing, session-id threading (`--resume`/`resume`/`--conversation`/`--resume`/`--session-id`), cost mapping, oversize/BoundedBuffer, process-tree kill. `grok.ts`: prompt via temp `--prompt-file` (no stdin support); normal runs use `--output-format streaming-messages-json` (Claude-compatible `assistant`/`result` envelope, reusing `extractGrokFinalText`/`grokActivityFromEvent` over the same shape as Claude's stream); structured runs use `--json-schema <inline JSON>`, which switches to a single pretty-printed terminal JSON document parsed at process close and carrying `structuredOutput`. Terminal success requires `type:"result"`, `subtype:"success"`, `is_error:false`, `stop_reason:"end_turn"` (or `stopReason` in the structured document), zero exit, and non-empty result — no success without an observed terminal event. `--reasoning-effort` accepts only `low|medium|high|xhigh` in 1.0.40; `off`/`minimal` map to `low`. Cost is native (`total_cost_usd`, or summed per-model `costUSD`), never estimated; no budget flag exists so `max_budget_usd` is recorded but unenforceable; no retries. `muse.ts`: `exec --json` MSP-schema JSONL envelopes (`payload_type`/`payload`, distinct from claude/codex/grok's flat event shape); prompt via temp `--prompt-file`, structured output via temp `--output-schema <FILE>` (file path, not inline JSON); no native system-prompt flag — `systemPrompt` folds into the prompt file, same as `agy.ts`. Root-run ownership is captured once from `runtime.command.accepted` (`command_id`) plus `session.run.linked`/`run.lifecycle.started` (tying that `command_id` to a `run_stream.id`) and checked on every later envelope (`isMuseRootRunEnvelope`): only a matching envelope's `run.terminal.completed`/`run.terminal.failed`/`run.output.delta` can affect the result — a nested or foreign run's own terminal event of either shape is ignored, never finalizing or failing the root. Terminal success requires `payload_type:"run.terminal.completed"` with non-empty `payload.text`; `run.terminal.failed`'s `payload.reason` is the error; if the root's own terminal never arrives (only a mismatched/foreign one did), the run fails closed as "exited without a terminal JSON event" rather than adopting the foreign text. `--reasoning-effort` maps Pi's six thinking levels 1:1 (`off→none`). Usage/cost never observed on any run — reported as `costKnown:false`, never estimated. `--session-id` resume verified for real: two independent `muse exec` processes sharing the same id reported the same session and the second recalled a fact only told to the first; `sessionId` is captured once from the root-establishing envelope, not overwritten by every subsequent one. No adapter-level retry; muse's own `meta` provider does its own internal retries (observed up to 10 attempts, exposed only as `task.lifecycle.status` narration, e.g. "retrying meta model stream in 60000ms (attempt 3/10)").
- `src/core/concurrency|timeout|process-tree|model|retention|progress|stream|parent-context|...` — shared primitives.
- `src/workflow/*` — `script-validation` (require `export const meta={apiVersion:1,name,description}`, reject `Date`/`Math.random` determinism lint), `script-worker` (`worker_threads`+`vm`, trusted JS — not a security sandbox), `runtime` (limits `maxAgentCalls 1000`/`maxLogs 500`/`maxLogLength 4000`), `tool→runtime→spawn` path with one frozen catalog snapshot (built-ins, shared roles, exact overrides, harness model/thinking), `journal` (`run-wf_*.jsonl`), `replay-cache` (`WORKFLOW_FINGERPRINT_POLICY_VERSION = tier-tools-v1+pi-coding-agent@<version>` over `subagentType`+effective descriptor+effective permission+context+phase+schema). Changed instructions invalidate reuse. A settings or role edit during the run does not alter that snapshot. `source`/`registry`/`structured-output`.
- `src/external-runs.ts` / `src/core/run-registry.ts` / `src/core/run-record.ts` / `src/core/run-inspection.ts` — supervision.

## 3. Execution contracts (the parts that bite)

- Concurrency: global `maxConcurrentSubagents` default 12, one `ConcurrencyLimiter` shared `Agent`+workflow, `acquire(signal)` queues, not per-harness. `Agent` is `executionMode:"parallel"`. Workflow parallelism requires `parallel([()=>agent(...)])`. 3× same harness (e.g. 3× `agy`) works when queued concurrently, not when sequentially `await`ed.
- Timeout: queue excluded, one `nestedActivitySeen` extension by fresh base capped 2× original. Pi abort cooperative (`session.abort()`), CLRIs SIGTERM→SIGKILL group kill (Windows `taskkill` mocked).
- Cost: Claude native `--max-budget-usd`; else recorded `budgetEnforceable:false`. Codex cost estimated from 3-model price map, `costEstimated:true`. Grok reports native cost (`total_cost_usd`, `costEstimated:false`) but has no enforcement flag, so it is also `budgetEnforceable:false`. Muse has never reported usage/cost on any run — `costKnown:false`, `costEstimated:false`, `budgetEnforceable:false`.
- Grok sandbox: kernel-enforced (Seatbelt macOS / Landlock Linux) at every tier — `readonly` = `--sandbox read-only`, `edit` = `--sandbox workspace`, `danger` = `--sandbox off`, always with `--permission-mode bypassPermissions` (bypass only removes the interactive prompt). `readonly`'s network block is Linux-only (macOS no-op); sandbox startup can fail closed on macOS hosts where `/var/run/docker.sock` resolves to a symlink — preserved as fail-closed rather than downgraded.
- Muse approval/sandbox: both ON by default, so every tier passes `--disable-approval` (headless runs must not hang on an interactive prompt). `readonly` additionally passes `--disable-write --disable-shell`; `edit` leaves the sandbox enabled with only approval bypassed; `danger` uses `--yolo`, which disables approval and the sandbox and *additionally trusts the workspace for this run* (loads its skills/rules) — a broader grant than an unsandboxed run alone, disclosed in full permission-help text rather than the terse `permissionLabel` caveat (which stays the universal `unsandboxed external CLI` for every danger tier). Nested-agent detection (`museHasNestedAgentActivity`) **always returns `false`**: every probe run only ever observed internal `reminder.agent.*` skill-reminder tasks, never a genuine delegation, and no confirmed real event shape exists — matching a speculative `task_kind` prefix was reviewed and rejected because it would let ordinary internal task activity spuriously grant the one-time nested-timeout extension.
- Pi child: `noExtensions/noSkills/noPromptTemplates/noThemes:true`, `noContextFiles:false` (project `AGENTS.md` text still loads, inert). Tiers `readonly:read/grep/find/ls`, `edit:+edit/write`, `danger:read/bash/edit/write`; explicit `tools:` intersected. Retry disabled in-memory **after** `resourceLoader.reload()` via `SettingsManager.applyOverrides`, never persisted. Cooperative abort only. No resume (in-memory session disposed, `resolveResume` errors clean). No hard budget.
- Auth preflights before session: closed thinking `off…xhigh`, `hasConfiguredAuth` sync, model resolve discriminated errors. Success = observed `agent_end.willRetry===false` + no terminal `stopReason:error/aborted` + non-whitespace final text + thinking-clamp disclosed.

## 4. Parent context & supervision

Context default none; `recent N`/`full` frozen before queue, one snapshot per workflow, excludes system/thinking/pending, >1MiB/images throw, `resume`+context mutually exclusive, disclosed on intent card + receipt. Supervision: blocking default, `background:true` returns `run_*`/`wf_*` after validation/registration, session-owned (not daemon), `external_runs` `list/inspect/wait/cancel` session/project scoped, wait outcome-only never cancels work, `all` returns early on unsuccessful selected workflow, cancel preserves reason, crash→`interrupted_or_uncertain` never retro-adopted.

Evidence: `runs/<run-id>/{events.ndjson,summary.json}` best-effort redacted, not secrecy boundary; retention prunes oldest completed >`maxRunRecords`, never active/interrupted/incomplete/damaged; `list` keyset, `inspect` byte-paged opaque base64url cursors (`MAX 64KiB`, stale fails), integrity `complete/incomplete/damaged`. Known gap proved: `run-inspection.outputFromEvent` has no `pi` case — failed Pi durable paging returns empty on `output` view (live result still present, `diagnostics` has raw events); live/terminal path unaffected.
